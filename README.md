# リアル人生ゲーム

学祭でスマートフォンから使うカード抽選アプリです。HTML / CSS / JavaScriptの画面をCloudflare Workersで配信し、グループモードはDurable ObjectsとWebSocketで同期します。

## 遊び方

「ひとりで遊ぶ」は既存の処理を維持しています。カード対象、所持金、位置、50マスでの終了、ブラウザへの保存・再開を利用できます。初期所持金は100,000円です。

「グループで遊ぶ」は以下の流れで利用します。

1. ホストが名前とカード対象（子供 / 大人）を選び、部屋を作ります。
2. 表示された6桁の部屋番号を伝えます。先頭の0も含めて入力してください。
3. 参加者は自分のスマートフォンで名前と番号を入力します。カード対象はホストの設定になります。
4. 2〜12人がそろったら、ホストが開始します。開始後の新規参加はできません。
5. 参加順にカードを引きます。結果・所持金・各プレイヤーの現在位置が全員に表示され、手番は自動で次の人に移ります。
6. 表示された「○マス進む / 戻る」に従い、実際の盤面で移動してください。

グループの現在位置は0マスから開始し、カードの移動数を本人の位置に加算します。1人用と同じく0〜50マスの範囲に収め、部屋内で共有・保存します。全員が50マスに到達した時点でゲームを終了し、1人用と同じデザインの結果画面へ切り替えます。自分の最終所持金と全員の最終所持金を表示し、「最初から遊ぶ」でモード選択に戻れます。位置表示を追加する前に作成した部屋は過去の移動履歴がないため、0マスから集計します。

先に50マスへ到達した人も参加順に手番を続け、その手番ではゴール後の専用ボーナスカードを引きます。子供は＋500・1,000・1,500・2,000円、大人は＋5,000・10,000・15,000・20,000円の各4枚で、移動はありません。位置は50マスに固定されます。ボーナス山札は通常山札とは別に部屋全体で共有し、一巡まで重複せず、使い切ったら再シャッフルします。全員ゴール後はボーナス抽選も終了します。

共有する1つの山札を開始時にシャッフルし、使い切るまで同じカードを引きません。使い切ったら再シャッフルします。一巡の境目では同じカードが続く場合があります。

画面を閉じても参加は維持されます。同じ端末・ブラウザの「参加中の部屋に戻る」で再接続できます。切断中は抽選を無効化し、自動再接続します。通常はWebSocketで即時同期し、通知を取りこぼした場合も5秒ごとの状態確認で復旧します。スマートフォンで画面を再表示した際にも状態を確認し、終了済みなら結果画面に切り替えます。切断した人の手番は飛ばしません。その人が戻ってから続けてください。ブラウザの参加情報を削除すると、その人として戻れません。部屋の削除や途中退出は未実装です。

## ローカル実行

カード設定画面は `/card-settings.html` に直接アクセスして開きます。ゲーム画面にはリンクを表示しません。子供用・大人用それぞれの通常カードとボーナスカードを追加・編集・削除できます。ボーナスカードの移動数は0で固定です。保存は現在のブラウザ内で、新しく始めるひとり用ゲームと、新しく作るグループの部屋に反映されます。グループではホストが選んだ対象の保存済みカードを部屋作成時にサーバーで検証・保存し、参加者全員で共有します。参加者側の設定は使用しません。進行中のゲームや作成済みの部屋は開始・作成時の設定を保持し、再接続後も同じカードを使用します。設定の反映にファイルの置き換えや再デプロイは不要です。JSONの読み込み・書き出しにも対応しています。「設定ファイルを出力」はアプリ全体の初期設定を変更するときに使用します。ボーナスカードも部屋作成時のホストの設定を保存し、ゴール後の抽選に使用します。以前保存した設定やJSONにボーナス設定がない場合は、従来のボーナスカードを補います。

Node.js 22以降とnpmを使用します。このフォルダで実行してください。

```sh
npm ci
npm run dev
```

<http://localhost:8787/> を開きます。Cloudflareへのログインは不要です。別のブラウザやシークレットウィンドウを使うと、複数プレイヤーを確認できます。タブ同士は参加情報の保存先が共通なので、別参加者の確認には別ブラウザを推奨します。

同じWi-Fiのスマートフォンから確認する場合は次を実行します。

```sh
npm run dev -- --ip 0.0.0.0
```

スマートフォンで `http://パソコンのLAN内IPアドレス:8787/` を開いてください。必要に応じてファイアウォールで8787番ポートを許可します。停止は `Ctrl+C` です。ローカルのDurable Objectデータは `.wrangler/` に保存され、本番とは別です。

## テストとビルド

```sh
npm test
npm run build
```

1人用の抽選・収支・保存・再開・確認キャンセル・終了を簡易DOMで検証します。グループ用はMiniflareのWorkers実行環境で、共有山札の一巡と再シャッフル、全接続への結果同期、認証、部屋の隔離、ホスト権限、手番、重複操作、再接続、Durable Objectの再生成後の復元を検証します。`build` はデプロイを行わず、バンドルと設定を確認します。

実機ではホストと参加者の両方から接続し、他人の番のボタンが無効であること、全員に同じ結果が出ること、再読み込み後も所持金と手番が維持されることを確認してください。

## Cloudflareへデプロイ

```sh
npm ci
npx wrangler login
npm test
npm run build
npm run deploy
```

Wranglerで目的のCloudflareアカウントを選択してください。複数アカウントがある場合は、必要に応じて `wrangler.jsonc` に `account_id` を設定します。既存のWorker名 `real-life-game` と配信先 `./public` は維持しています。デプロイ後のHTTPS URLを全員に共有してください。

`wrangler.jsonc` に `ROOMS` バインディングと `v1` migration（`new_sqlite_classes: ["GameRoom"]`）を定義しています。初回デプロイでSQLite-backed Durable Objectの名前空間が作成されるため、Dashboardでの手動作成やバインディング追加は通常不要です。既存のカスタムドメインを使う場合はそのWorkerへの割り当てを確認してください。適用済みmigrationのタグやクラス名は変更しないでください。

## 構成

| ファイル | 役割 |
| --- | --- |
| `public/index.html` | モード選択、1人用、部屋参加、グループ画面 |
| `public/style.css` | 既存デザイン、スマートフォン表示、手番の強調 |
| `public/cards.js` | 共通カードと初期所持金、カード対象 |
| `public/script.js` | 既存の1人用ロジック・保存・画面処理 |
| `public/rooms.js` | グループ画面、WebSocket接続・再接続 |
| `worker.mjs` | 部屋作成・参加APIとGameRoom Durable Object |
| `wrangler.jsonc` | 静的配信、Worker、DOバインディング・migration |
| `tests/game.test.cjs` | 既存1人用テスト |
| `tests/cards.test.cjs` | カード対象と山札の検証 |
| `tests/goal.test.cjs` | 全員ゴール・専用ボーナス・終了後の抽選拒否 |
| `tests/room-ui.test.cjs` | モード選択・グループ画面・結果表示・通知取りこぼしからの復旧 |
| `tests/worker.test.cjs` | Workers / WebSocket統合テスト |

1部屋につき1つのDurable Objectを使用します。参加者と参加順、認証トークン、手番、所持金、現在位置、カードのスナップショット、共有山札と山札位置、開始状態、直前の結果、更新番号を永続保存します。クライアントには他人の認証トークンや山札を公開しません。

開始・抽選はWebSocket経由で送信します。DOが認証済み接続と保存済みの手番を照合し、更新番号を使って二重操作を拒否します。参加・開始・抽選の更新を保存後、部屋内の全接続へ状態を配信します。WebSocket Hibernation APIで接続を管理し、DOが再生成されても保存状態と接続の認証情報を復元します。

通常カードは `public/cards.js` の `audiences`、ゴール後の専用カードは `bonusCards` に追加してください。専用カードは金額を正の数、移動を0にしてください。開催中の部屋は作成時のカードを保持し、変更は新しい部屋に反映します。1人用の保存互換性に影響する変更では `audienceGame` のバージョンも更新してください。

詳細な仕様は [設計書](docs/design.md) を参照してください。起動・テスト・公開はこのREADMEのコマンドに統一しています。

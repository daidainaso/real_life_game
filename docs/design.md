# 現行設計

学祭のリアル人生ゲームで使う電子カードと財布です。カードの指示に従って実際の盤面を移動します。配信先はCloudflare Workers、静的ファイルは public/ です。

## カード対象と画面

開始画面で子ども向け・大人向けのカードと、ひとりで遊ぶ・グループで遊ぶを選びます。対象の選択は大きなボタンと選択中の表示で示します。ゲーム中は対象を切り替えません。

上部のタイトルからモード選択へ戻れます。1人用の記録とグループの参加情報は維持します。終了画面の「最初から遊ぶ」もモード選択へ戻ります。

## 1人用

初期所持金は100,000円、位置は0マスです。カードの収支と移動数を加算し、位置を0〜50マスに収めます。50マスに到達すると自動終了し、最終所持金を表示します。所持金のマイナスは許可します。

選んだ対象の山札をシャッフルし、一巡までは同じカードを引きません。使い切ると再シャッフルします。一巡の境目では同じカードが続く場合があります。現在の画面では学生・社会人・老後への自動切り替えは使用しません。

保存先は localStorage の lifeGame.state です。形式は schemaVersion: 3、対象別設定は version: 4 です。金額・位置・山札・直前のカード・抽選回数・状態などを検証して再開します。復元時にカードの効果は再適用しません。破損した記録は新規開始を確定するまで上書きしません。保存不可でもページを開いている間は遊べます。

## グループとサーバー

1部屋につき1つのGameRoom Durable Objectを使用し、SQLite-backedストレージへ状態を保存します。部屋番号はランダムな6桁です。番号の衝突は作成先のDOで検出して再試行します。

2〜12人が名前を入力して参加できます。作成者がホストとなり、部屋のカード対象を決めます。同名参加・開始後の追加参加は拒否します。参加順がそのまま手番の順になります。

サーバーは参加者と認証情報、所持金と現在位置、手番、通常・ボーナスのカードと山札位置、開始・終了状態、直前の結果、更新番号を保存します。カードは部屋作成時のスナップショットを使います。通常山札とボーナス山札は別々に部屋全体で共有します。

開始・抽選はWebSocketから送信します。認証済み接続と保存されたホスト・手番を照合し、更新番号で重複操作を拒否します。クライアントが申告した手番やカード対象は信用しません。更新を保存した後に、部屋内の全接続へ各参加者用の状態を配信します。他人の認証トークンと山札順は公開しません。

WebSocket Hibernation APIを使用し、接続の認証情報をattachmentへ保存します。DO再生成時は保存状態を読み込みます。通知を取りこぼした場合は5秒ごとの認証付きGETで状態を確認し、画面再表示時も確認します。古い更新番号の応答は適用しません。未確定の抽選は自動で再送しません。

## グループのゴールと終了

本人が引いた通常カードで所持金と位置を更新します。位置は0〜50マスに収めます。先に50マスへ到達した人も手番を続け、その後は移動なしの専用ボーナスカードを引きます。

| 対象 | ボーナスカードの金額 |
| --- | --- |
| 子ども向け | ＋500・1,000・1,500・2,000円 |
| 大人向け | ＋5,000・10,000・15,000・20,000円 |

通常・ボーナスとも一巡まで重複せず、使い切ると再シャッフルします。全員が50マスに到達したらサーバーで終了を確定し、以後の抽選を拒否します。部屋内の全員の画面が結果画面へ切り替わり、自分と全員の最終所持金を表示します。通知を受け取れなくても状態確認や再接続で終了状態を復元します。

## 再開と制限

参加情報は localStorage の lifeGame.room.v2 に部屋番号と本人のトークンを保存します。同じ端末・ブラウザから再接続できます。画面を閉じても退出にはなりません。切断者の手番は維持します。

部屋削除、途中退出、切断者の手番を飛ばす機能、端末間の参加情報の引き継ぎはありません。ブラウザの参加情報を削除すると同じ参加者として復帰できません。実際に盤面で移動したかは判定しません。

## 検証と運用

npm test で1人用、対象別カード、ゴール後の専用カード、グループ画面、Workers実行環境の統合テストを実行します。npm run build はデプロイせずにバンドルと設定を確認します。実機の表示と接続は別途確認してください。

ローカル実行とデプロイの手順は [README](../README.md) にまとめています。公開時はWranglerのmigrationでDOを作成します。適用済みのmigrationタグ・クラス名を変更しないでください。
